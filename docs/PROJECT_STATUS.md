# Cardo: статус проекта

Flutter-клиент совместного канбана. Сервер (Go) живёт в отдельном репозитории `Cardo-backend`.

Статус на 3 ноября 2026 года. Ветка `develop` после мержа этапа 3 (`f9e203f`), 2797 тестов.

## Коротко

| Этап | Что входит | Статус |
|---|---|---|
| Основа | Дизайн-система, локализация, экран доски, шторка карточки | Готово, в `develop` |
| 1. Вход и доски | REST, токены, вход, регистрация, профиль, список досок | Готово, в `develop` |
| 2a. Ядро синхронизации | WebSocket, порядок событий, переподключение | Готово, в `develop` |
| 2b. Экраны синхронизации | Офлайн-баннер, сводка, отклонённые, потеря доступа | Готово, в `develop` |
| 3. Содержимое доски | Создание карточек и колонок, архив колонки | Готово, в `develop` |
| 4. Участники и доступ | Участники, инвайты, настройки доски | Не начато |
| 5. Полировка и релиз | Правки текстов, README, релиз в `main` | Не начато |

**Важно:** приложение целиком проверено на тестах и фейковом сервере по протоколу. Агенты и координатор на настоящем сервере его не запускали, запуск на Windows ведёт пользователь, его результат здесь не зафиксирован. Ветка `main` отстаёт: в ней нет этапов 1, 2a, 2b, 3, шторки карточки и английского.

## Что реализовано

### Дизайн-система
- Токены цветов, типографики, радиусов, отступов, размеров, теней и анимаций для светлой и тёмной темы.
- Цветовая схема собрана вручную, сырые значения разрешены только в `lib/theme/`.
- Шрифты Bricolage Grotesque, Geist и Geist Mono лежат в репозитории. В Bricolage нет кириллицы, поэтому для неё работает запасной Geist.
- Общие виджеты: `CardTile`, `ConnectionPill`, `RoleBadge`, `AvatarStack`, `CardoLogo`, `ConflictBanner`.

### Локализация
- Русский и английский, язык выбирается по системе. Для любого языка, кроме русского, показывается английский.
- Числа и даты форматируются по текущему языку.
- Тест падает, если в одном из языков не хватает строки.

### Вход и профиль
- Регистрация с выбором цвета аватара, вход, профиль, выход.
- Access-токен хранится в памяти, refresh-токен в защищённом хранилище.
- Токен обновляется заранее и при ответе 401. Несколько одновременных запросов обновляют его один раз.
- Сдвиг часов устройства не ломает обновление токена.
- Сессия восстанавливается при запуске до показа интерфейса.
- Адрес сервера не хранится в коде, он задаётся файлом `env/local.json`.

### Список досок
- Список на телефоне и плитка на широком экране, пустое состояние, ошибка с повтором.
- Создание доски.

### Доска
- Три раскладки по ширине: до 600 (вкладки и колонки страницами), 600–840 (горизонтальный скролл), от 840 (сайдбар, колонки, панель карточки).
- Перетаскивание карточек внутри колонки и между колонками, альтернатива для скринридера.
- Режим наблюдателя: плашка роли, нет создания и перетаскивания.
- Оптимистичный интерфейс: действие видно сразу, отклонённое сервером исчезает с понятным сообщением.

### Карточка
- Шторка на телефоне и панель на широком экране.
- Правка заголовка и описания, счётчик символов, автор и время создания.
- Черновик описания не теряется при закрытии шторки.
- Конфликт описания: если текст изменил другой участник, появляется блок «Перезаписать» или «Отменить».

### Синхронизация
- WebSocket с токеном в заголовке, handshake с `last_seq`, дельта или снапшот.
- Состояние строится только из событий сервера, применяемых строго по `seq`.
- Пропущенные события догружаются через REST. Если их уже нет в журнале, загружается снапшот.
- Обновление токена внутри сокета, ping со стороны клиента, обработка всех кодов закрытия.
- Переподключение с паузой от 0,5 до 30 секунд и обратным отсчётом в шапке.
- Офлайн-очередь уходит темпом ниже лимита сервера, в исходном порядке, с теми же `op_id`.
- Присутствие на доске, смена роли на лету, переименование доски.

### Содержимое доски
- Создание карточки прямо внизу колонки, с необязательным описанием. Черновик хранится отдельно для каждой колонки.
- Правка заголовка на самой карточке. Запускается карандашом в шторке или панели и действием скринридера.
- Создание колонки: поле в ряду вкладок на телефоне, кнопка «+ Колонка» на широком экране.
- Меню колонки: переименование, сдвиг влево и вправо, архив с подтверждением и числом карточек.
- Операции над новой карточкой или колонкой ждут подтверждения её создания. При отказе зависимые операции снимаются и попадают в журнал отказов.

### Экраны синхронизации
- Офлайн-баннер «Нет сети · N изменения ждут» с кнопкой «Повторить».
- Сводка после переподключения и список отклонённых операций с причинами.
- Диалог при исключении с доски или её удалении. Несохранённый текст можно скопировать.
- Переподключение при возврате приложения из фона.

### Качество
- 2797 тестов в `develop`, в том числе тест сходимости: несколько клиентов, сотни случайных операций, разрывы связи, сверка с независимым эталоном.
- Policy-тесты: нет сырых значений вне темы, нет комментариев, нет зашитых адресов и локалей, соблюдены границы слоёв.
- Чистая архитектура: `domain` на чистом Dart, без Flutter.
- CI на GitHub Actions: форматирование, анализатор, свежесть локализации, тесты.

## Известные ограничения и отложенное

### Клиент
- Новый движок синхронизации большой, около 780 строк, его стоит разбить.
- Цикл импортов между `boards/data` и `board/data/realtime`.
- `CardViewData` всё ещё содержит доменный `CardModel`, от него зависит перетаскивание.
- Операция, повторённая после временного отказа сервера, может обогнать более позднюю правку той же карточки. Придёт лишний конфликт версии, данные не расходятся.
- Отказы в очереди, накопленной до первого подключения, приходят отдельными уведомлениями, а не сводкой.
- У пакета операций после переподключения нет таймаута на случай, если сервер не ответит.
- Автор конфликта определяется по последней правке карточки, а не именно описания.
- На новых экранах синхронизации тёмная тема тестами не проверялась.
- Текст формы новой карточки и правки заголовка теряется без уведомления при уходе с доски или удалённом архиве колонки.
- Отклонённая новая колонка ещё 2,4 секунды видна с меню и кнопкой добавления, действия в это время ничего не делают.
- Обход `refreshPagerExtent` на телефоне может прервать жест пролистывания, когда другой участник создаёт или архивирует колонку.
- Цвет маркера колонки зависит от позиции: новая колонка становится «Готово», прежняя последняя перекрашивается в «Ревью».
- Если перенести карточку в отклонённую колонку, а потом в другую, второй перенос получит ложный конфликт версий.
- Кнопка «Добавить» в форме карточки при открытой клавиатуре на устройстве не проверялась.
- Физический телефон не подключится к серверу по HTTP: debug-сборка Android разрешает его только для `localhost`, `127.0.0.1` и `10.0.2.2`.

### Сервер
- Нет CORS, поэтому приложение не работает в браузере. WebSocket в браузере к тому же не может передать токен заголовком.
- Если ответ на обновление токена потерялся, следующая попытка считается повторным использованием, и сервер отзывает все сессии. Окна на повтор нет.
- В отклонении операции нет поля `actor_id`, поэтому клиент не может точно назвать автора конфликта.

### Вне MVP (из ТЗ)
- Исполнитель, дедлайн, чеклисты, передача владения, восстановление из архива.
- Сохранение офлайн-очереди на диск между запусками.
- Совместное редактирование описания, push-уведомления, вложения.

## Как запустить

```bash
copy env\example.json env\local.json
```

Впишите адрес в `env/local.json`:

```json
{"API_BASE_URL": "http://localhost:8080"}
```

Затем запустите приложение:

```bash
flutter run -d windows --dart-define-from-file=env/local.json
```

Сервер поднимается в его репозитории командой `docker compose up`, инструкция в README бэкенда.
